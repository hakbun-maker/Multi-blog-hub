## 1. 한 줄 정의

> **"보고 끝이 아니라, 클릭 한 번으로 액션 적용까지 가는 매일 사용 수익 의사결정 도구"**

기존 `/dashboard`(현재 스냅샷)와 분리. `/stats`는 **delta + 알림 + 추천 액션** 으로 매일 새 가치를 제공.

---

## 2. 사용자 시나리오

### 매일 시나리오 (5분 이내)

1. **아침** `/stats` 진입
2. **TOP 브리핑** 5초 스캔 — 어제 대비 변화·새 알림 카운트·오늘 할 일 3개
3. 추천 액션 중 **클릭 한 번**으로 적용 가능한 것 처리 (광고 슬롯 추천, 제목 재제안 등)
4. 시간 여유 있으면 **숨은 보석 / 진단 / 최적화** 섹션 스크롤
5. 페이지 떠남

### 월 1회 시나리오 (10-20분)

1. 아래 **시뮬레이션 섹션** 펼침
2. 슬라이더 4개 조작 → 다음달 예상 수익 변화 시뮬
3. 비교 결과 기반으로 **그달 전략 결정** (발행 빈도, 카테고리 비중 등)

## 3. 페이지 구조 (5섹션)

```
/stats
│
├─ 🌅 [TOP] 오늘의 브리핑                    ← 매일 가치 (delta + 알림 + 액션)
│
├─ 🌟 [섹션 1] 숨은 보석                      ← 즉시 액션
│
├─ 🎯 [섹션 2] 다음달 수익 예측 + 진척도       ← 압축 표시
│
├─ 📊 [섹션 3] 진단 (펼침 기본)               ← 탐색
│
├─ ⚙️ [섹션 4] 최적화 (펼침 기본)             ← 탐색
│
└─ 🎮 [섹션 5] 시뮬레이션 (접힘 기본)          ← 월 1회만
```

### 3.1 🌅 TOP — 오늘의 브리핑

| 요소 | 내용 | 데이터 소스 |
|---|---|---|
| Delta 카드 3개 | 어제 대비 수익 / 조회수 / CTR — 화살표 + % 변화 | GA4 + AdSense (1h cache) |
| 새 알림 배지 | "숨은 보석 N개" / "덮이는 글 M개" — 클릭 시 해당 섹션으로 스크롤 | 자동 임계치 검사 |
| 오늘 할 일 카드 (3개) | AI 추천 액션 — 각각 [지금 적용] / [나중에] / [무시] 버튼 | 통계 분석 + 휴리스틱 룰 |

**오늘 할 일 카드 예시**:
```
🟢 "Top 5 글 자동 리라이팅 큐에 추가"
   예상 효과: 4주 후 노출 +30%
   [지금 적용 →]  [나중에]  [무시]

🟡 "광고 슬롯 'left_sidebar_ad' 비활성화"
   사유: 30일 viewability 12% (효과 없음)
   [지금 적용 →]  [나중에]  [무시]

🟢 "신규 키워드 5개 발행 큐에 추가"
   카테고리: 의료 (RPM 12,000원)
   [지금 적용 →]  [나중에]  [무시]
```

### 3.2 🌟 섹션 1 — 숨은 보석

> 노출 ≥ 1,000 + CTR < 2% (임계치는 조정 가능) 글 자동 식별

| 요소 | 내용 |
|---|---|
| 카드 리스트 | 후보 글 5개 — 노출수 / CTR / 추천 새 제목 3개 (AI 즉석 생성) |
| 액션 | [제목 변경] 버튼 — 클릭 시 새 제목으로 즉시 업데이트 + 발행 |

### 3.3 🎯 섹션 2 — 다음달 예측 + 진척도

| 요소 | 내용 |
|---|---|
| 예측 카드 | "이대로 가면 다음달 약 X원 (작년 동월 대비 +Y%)" |
| 진척도 게이지 | 사용자가 설정한 월 목표 대비 현재 진척률 (예: 73%) |
| 달성 가능성 | 현재 페이스로 예상 달성 확률 ("65% 가능") |

### 3.4 📊 섹션 3 — 진단 (펼침 기본)

| 위젯 | 시각화 | 데이터 |
|---|---|---|
| ROI 랭킹 (Top 10 / Bottom 5) | 표 + 정렬 | 누적 수익 / 발행 후 일수 |
| 카테고리 파레토 차트 | Bar + 누적선 | 카테고리별 수익 합 |
| 다차원 드릴다운 | 트리/탭 | 카테고리 → 키워드 → 글 → 슬롯 |

### 3.5 ⚙️ 섹션 4 — 최적화 (펼침 기본)

| 위젯 | 시각화 | 데이터 |
|---|---|---|
| 광고 슬롯별 수익 비교 | Bar | AdSense 슬롯별 estimatedEarnings |
| 카테고리 × RPM 매트릭스 | Heatmap | 카테고리·블로그 RPM |
| Viewability 점수 분포 | Donut | AdSense `viewable_impressions_percent` |

### 3.6 🎮 섹션 5 — 시뮬레이션 (접힘 기본)

| 요소 | 내용 |
|---|---|
| 슬라이더 4개 | 발행 빈도(주/회) / 광고 슬롯 수 / 카테고리 의료 비중(%) / 리라이팅 수 |
| 결과 라인차트 | 슬라이더 조작 시 30/60/90일 후 예상 수익 실시간 갱신 |
| 시나리오 비교 (선택 보류) | 미선정 — 추후 |

## 4. 데이터 모델

### 4.1 데이터 소스

| 출처 | 메트릭 | 사용 위치 |
|---|---|---|
| **GA4 Data API** | `screenPageViews`, `totalUsers`, `sessions`, `userEngagementDuration` | TOP delta, ROI 랭킹, 체류시간 |
| **AdSense Management API** | `estimatedEarnings`, `clicks`, `impressions`, `viewable_impressions_percent`, `pageRPM` | 모든 수익 관련 위젯 |
| **GSC Search Analytics API** | `impressions`, `clicks`, `ctr`, `position` | 숨은 보석 (CTR 낮음 식별) |
| **Supabase (자체)** | `posts`, `daily_stats`, `blogs.layout_config.ads` | 글 메타·카테고리·발행일 |

### 4.2 캐시 전략 — 1시간 TTL

```typescript
// 새 테이블: stats_cache
{
  user_id: uuid,
  cache_key: text,          // 'overview' | 'roi-ranking' | 'pareto' | ...
  data: jsonb,              // 가공된 통계 데이터
  computed_at: timestamptz,
  expires_at: timestamptz,  // computed_at + 1h
}
```

- 페이지 진입 시 `expires_at > now()` 면 캐시 사용
- 만료 시 GA4·AdSense·GSC 동시 호출 → 가공 → 캐시 저장
- 사용자가 [수동 갱신] 버튼 누르면 캐시 무효화

### 4.3 시뮬레이션 모델 — 과거 데이터 선형 회귀

```typescript
// 입력: 사용자가 슬라이더로 조작한 4개 변수
interface SimulationInput {
  publishesPerWeek: number      // 발행 빈도
  totalAdSlots: number          // 활성 광고 슬롯 수
  medicalCategoryRatio: number  // 의료 카테고리 비중 (0~100%)
  rewriteCount: number          // Top X 글 리라이팅 수
}

// 출력: 30/60/90일 후 예상 수익
// 모델: y = β0 + β1·x1 + β2·x2 + ... (단순 선형 회귀, 과거 90일 데이터 학습)
```

**학습 데이터**: 최근 90일 `daily_stats` + `posts` 테이블
**계산 위치**: 서버 (`/api/stats/simulate` POST), 클라이언트는 슬라이더 debounce 500ms

## 5. API 라우트 (신규)

| 메서드 | 경로 | 역할 |
|---|---|---|
| GET | `/api/stats/overview` | TOP 브리핑 데이터 (delta + 알림 카운트 + 추천 액션) |
| GET | `/api/stats/hidden-gems` | 숨은 보석 후보 + AI 새 제목 제안 |
| GET | `/api/stats/forecast` | 다음달 예측 + 목표 진척도 |
| GET | `/api/stats/diagnosis` | ROI 랭킹 + 파레토 + 드릴다운 데이터 |
| GET | `/api/stats/optimization` | 슬롯 비교 + RPM 매트릭스 + viewability |
| POST | `/api/stats/simulate` | 시뮬레이션 (입력 슬라이더 → 출력 예상 수익) |
| POST | `/api/stats/action/apply` | 행동 카탈로그 액션 실행 (단순 자동 처리만) |

각 GET 엔드포인트는 위 캐시 전략 적용.

---

## 6. 액션 자동화 범위

### ✅ 클릭 한 번 자동 처리

- 광고 슬롯 ON/OFF 토글
- 광고 슬롯 위치 추천 적용 (사용자 ads_config 업데이트)
- 글의 SEO 제목 변경 (AI 제안 중 선택 시)
- "리라이팅 큐 추가" → 작업 큐에 적재 (실제 리라이팅은 비동기)

### ⚙️ 제안만, 수동 적용

- 새 글 작성 (글쓰기 페이지로 이동만)
- 카테고리 비중 조정 (제안만, 사용자가 직접 발행 계획 조정)
- 글 본문 리라이팅 결과 검토·발행 (AI 초안 → 에디터 진입)

## 8. 구현 우선순위 (TASKS 미리보기)

### Phase A — 데이터 인프라 (1주)
- 신규 테이블 `stats_cache` 마이그레이션
- 7개 API 라우트 스켈레톤
- GA4·AdSense·GSC 데이터 수집기 + 1h 캐시

### Phase B — TOP 브리핑 + 숨은 보석 (1주)
- `/stats` 페이지 신규 라우트
- TOP 브리핑 컴포넌트 (delta 카드 + 알림 배지 + 추천 액션 카드)
- 숨은 보석 섹션 + AI 제목 제안 + 적용 버튼
- 행동 카탈로그 액션 핸들러 4종

### Phase C — 진단 + 최적화 (1주)
- ROI 랭킹 / 파레토 / 드릴다운 (recharts)
- 슬롯 비교 / RPM 매트릭스 / viewability (recharts heatmap)

### Phase D — 시뮬레이션 + 예측 (1주)
- 단순 선형 회귀 모델 (과거 90일 데이터 학습)
- 슬라이더 UI + debounce 500ms
- 다음달 예측 카드 + 진척도 게이지

### Phase E — 정리 (3일)
- 사이드바 메뉴 라벨 검토
- 기존 `/stats` 폐기 또는 마이그레이션
- 모바일 레이아웃 검수

## 9. 미해결·관찰 항목

- viewability 측정의 정확도 — AdSense API의 `viewable_impressions_percent` 만으로 충분한가? 부족하면 IntersectionObserver 보조 추가
- "숨은 보석" 임계치 — 노출 1,000 / CTR 2% — 운영 데이터 보고 조정
- 모바일 — 데스크탑 5섹션을 모바일에서 어떻게 stack? (1차 구현은 단순 세로 stack, 2차에 개선)
- 사이드바 메뉴 라벨 — "통계" 그대로 vs "수익 진단" 같은 새 라벨 — 1차는 "통계" 유지, 사용해보고 결정
