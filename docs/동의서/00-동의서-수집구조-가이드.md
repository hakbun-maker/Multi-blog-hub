## 1. 동의서 전체 목록 및 수집 시점

### 계층형 동의 (Layered Consent) 구조

사용자 이탈 방지와 법적 안전성을 동시에 달성하기 위해, **사용자가 해당 기능을 처음 만나는 시점에 필요한 동의만 받는** 방식을 채택합니다.

---

### 1단계: 회원가입 시 (필수)

| # | 동의서 | consent_type | 필수 여부 | UI 방식 |
|---|--------|-------------|----------|---------|
| 01 | 서비스 이용약관 | `tos` | 필수 | 체크박스 + 전문 보기 링크 |
| 02 | 개인정보 처리방침 | `privacy` | 필수 | 체크박스 + 전문 보기 링크 |
| — | 마케팅 수신 동의 | `marketing` | 선택 | 체크박스 |

```
회원가입 화면 UI:
┌──────────────────────────────────────────┐
│  [전체 동의] ← 편의용 토글               │
│                                          │
│  ☑ [필수] 서비스 이용약관    [전문 보기 >]│
│  ☑ [필수] 개인정보 처리방침  [전문 보기 >]│
│  ☐ [선택] 마케팅 수신 동의   [전문 보기 >]│
│                                          │
│              [가입하기]                   │
└──────────────────────────────────────────┘

※ "전문 보기"는 모달 또는 새 탭으로 전체 문서 표시 필수
※ 각 항목은 별도 체크박스 (하나로 묶으면 법적 무효)
※ 전체 동의 토글은 편의 기능이며, 개별 체크 해제 가능해야 함
```

### 2단계: 기능 최초 사용 시 (Just-in-Time Consent)

| # | 동의서 | consent_type | 수집 시점 | UI 방식 |

### 3단계: 요금제 변경 시

업그레이드 시 새로 열리는 기능에 대한 미수집 동의만 추가로 표시합니다.

```
예: Basic → Growth 업그레이드 시
신규 기능: 다국어, SNS 자동배포, 자동 글쓰기 파이프라인, 쿠팡파트너스

→ 결제 확인 화면에서:
  ☑ 자동화 처리 동의 (automation) — 자동 글쓰기 파이프라인 사용을 위해
  ※ SNS, 쿠팡 등은 해당 기능 최초 사용 시 개별 동의
```

## 2. DB 스키마: user_consents 테이블

```sql
CREATE TABLE user_consents (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  consent_type    VARCHAR(50) NOT NULL,
  consent_version VARCHAR(10) NOT NULL,   -- '1.0', '1.1' 등
  agreed_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  ip_address      INET,
  user_agent      TEXT,
  method          VARCHAR(30) NOT NULL,   -- 'signup_checkbox', 'inline_panel', 'modal', 'upgrade_flow'
  revoked_at      TIMESTAMPTZ,            -- NULL이면 유효, 값이 있으면 철회됨
  revoked_reason  TEXT,

  UNIQUE(user_id, consent_type, consent_version)  -- 동일 버전 중복 동의 방지
);

-- 인덱스
CREATE INDEX idx_user_consents_user ON user_consents(user_id, consent_type);
CREATE INDEX idx_user_consents_active ON user_consents(user_id, consent_type)
  WHERE revoked_at IS NULL;

-- RLS
ALTER TABLE user_consents ENABLE ROW LEVEL SECURITY;
CREATE POLICY users_own_consents ON user_consents
  FOR ALL USING (user_id = auth.uid());
```

### consent_type 유효값

```sql
ALTER TABLE user_consents ADD CONSTRAINT user_consents_type_check
  CHECK (consent_type IN (
    'tos',                      -- 서비스 이용약관
    'privacy',                  -- 개인정보 처리방침
    'marketing',                -- 마케팅 수신 (선택)
    'api_key_storage',          -- API 키 보관
    'automation',               -- 자동화 처리
    'sns_oauth_instagram',      -- SNS: Instagram
    'sns_oauth_twitter',        -- SNS: X (Twitter)
    'sns_oauth_threads',        -- SNS: Threads
    'affiliate_marketing',      -- 제휴마케팅
    'adsense_oauth',            -- AdSense 연동
    'blog_platform_tistory',    -- 블로그: Tistory
    'blog_platform_wordpress'   -- 블로그: WordPress
  ));
```

## 3. 동의 버전 관리 테이블

```sql
CREATE TABLE consent_versions (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  consent_type    VARCHAR(50) NOT NULL,
  version         VARCHAR(10) NOT NULL,
  title           TEXT NOT NULL,           -- "서비스 이용약관 v1.1"
  summary         TEXT,                    -- 개정 요약
  content_url     TEXT,                    -- 전문 URL 또는 경로
  effective_date  DATE NOT NULL,           -- 시행일
  created_at      TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE(consent_type, version)
);
```

## 4. API 엔드포인트

| 엔드포인트 | 메서드 | 설명 |
|-----------|--------|------|
| `/api/consents` | GET | 회원의 전체 동의 현황 조회 |

## 5. 프론트엔드 구현 가이드

### 5-1. 동의 체크 유틸리티

```typescript
// lib/consents/checkConsent.ts
async function hasValidConsent(
  userId: string,
  consentType: string
): Promise<boolean> {
  const { data } = await supabase
    .from('user_consents')
    .select('id, consent_version')
    .eq('user_id', userId)
    .eq('consent_type', consentType)
    .is('revoked_at', null)
    .order('agreed_at', { ascending: false })
    .limit(1)
    .single()

  if (!data) return false

  // 최신 버전과 비교
  const latestVersion = await getLatestConsentVersion(consentType)
  return data.consent_version === latestVersion
}
```

## 6. 동의 철회 시 연쇄 처리

| 철회 동의 | 연쇄 처리 |
|----------|----------|
| `api_key_storage` | 모든 API 키 즉시 삭제 → AI 글쓰기, 키워드 탐색, 이미지 생성 기능 중단 |
| `automation` | 수익화 로켓 비활성화 → 진행 중 작업 완료 후 중단 |
| `sns_oauth_*` | 해당 SNS OAuth 토큰 삭제 → 해당 플랫폼 자동 배포 중단 |
| `affiliate_marketing` | 제휴 자동 삽입 OFF → 이후 글에 삽입 안됨 |
| `adsense_oauth` | AdSense OAuth 토큰 삭제 → BlogGrade 갱신 중단 |
| `blog_platform_*` | 해당 플랫폼 인증 삭제 → 자동 발행 중단 |
| `tos` 또는 `privacy` | 서비스 이용 자체 불가 → 탈퇴 안내 |

---

## 7. 동의 이력 보관 규정

| 데이터 | 보관 기간 | 근거 |
|--------|----------|------|
| 동의 기록 (agreed_at, ip, method) | 동의 철회 후 3년 | 전자상거래법 제6조 |
| 철회 기록 (revoked_at, reason) | 철회 후 3년 | 전자상거래법 제6조 |
| 약관 버전 원문 | 영구 보관 | 분쟁 대비 |

**절대 삭제 금지**: 개정 전 동의 이력은 법적 증거로 활용될 수 있으므로, 서비스 운영 중에는 삭제하지 않습니다.
